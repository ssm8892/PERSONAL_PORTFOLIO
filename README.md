# PERSONAL_PORTFOLIO

11/7 - Wiped entire repo clean. Creating new portfolio version.

A personal portfolio built with **Next.js 16** (App Router, React 19, TypeScript, Cache Components).

- **Home** (`/`): a full-screen brain. Its folds are grown with a reaction-diffusion simulation. The left hemisphere renders them as a glowing circuit board with signal pulses (Developer). The right hemisphere paints them as warm ink with a brush trail that follows your cursor (Artist). Hover a side to light it up from where your cursor is, then click to fly in.
- **Developer** (`/developer`): projects, papers and talks with filters. GitHub stars and language, plus a "More on GitHub" list, are fetched on the server and cached hourly.
- **Artist** (`/artist`): a masonry gallery with a full-screen viewer (arrow keys / swipe) and a shelf of sketchbooks.
- **Sketchbook** (`/sketchbooks/<id>`): a 3D page-flip book. You can:
  - drag a page (it follows your finger and carries your flick's momentum)
  - tap the page edges, use ← → / Home / End, or scrub to any page
  - on phones, read one page at a time

## Develop

```sh
npm install
npm run dev        # http://localhost:3000
npm run build      # production build
npm run lint
```

## Add your content

Everything you'd edit lives in `content/` (typed, so mistakes show up in your editor):

| File | What's in it |
| --- | --- |
| `content/site.ts` | Name, tagline, GitHub username, links (email, LinkedIn, résumé), page headlines |
| `content/developer.ts` | Projects, papers, talks: title, description, tags, `repo: "owner/name"`, links |
| `content/artist.ts` | Gallery pieces and sketchbooks (any number of books, any number of pages) |

Images go in `public/gallery/` and `public/sketchbooks/<book-id>/`, referenced from the site root (`"/gallery/piece.jpg"`). The current files are generated placeholders; delete them when you add your own.

Tips:
- **Sketchbook pages** look best as scans/photos on a light background. Pages use `mix-blend-mode: multiply`, so white paper in a scan disappears into the book's paper.
- Set `aspect` on a sketchbook (page width ÷ height) to match the real book, e.g. `0.707` for A-series paper.
- GitHub's anonymous API allows 60 requests/hour. Set a `GITHUB_TOKEN` environment variable on your host to lift that.

## The brain

`public/brain.json` is generated by `scripts/generate-brain.mjs` (run with `npm run brain`, about 10 s):

1. A Gray-Scott reaction-diffusion simulation runs inside two hemisphere-shaped masks. Its maze pattern reads as cortical folds.
2. Marching squares trace the folds into paths.
3. The left side is cut into short runs and routed at 0°/45°/90° like PCB traces. The right side stays smooth.

Tweak the seed, grid or `F`/`K` parameters in the script to grow a different brain. The browser only draws the precomputed paths (`components/brain/renderer.ts`). Static detail is pre-rendered into offscreen canvases once per resize, so each frame is a few image copies plus the moving pulses.

## Deploy

Vercel works with no configuration. Any Node host works with `npm run build && npm start`.

## Structure

```
app/                    routes (home, (site)/developer, (site)/artist, sketchbooks/[id])
components/brain/       landing-page brain: React shell + canvas renderer
components/sketchbook/  page-flip reader: React shell + flip engine
components/artist/      gallery + viewer
components/developer/   work grid + filters
content/                ← edit these
lib/                    spring physics, GitHub fetching, icons
scripts/                brain generator
styles/                 page styles
```

## Motion & accessibility

- One set of easing curves in `app/globals.css` (`--ease-out`, `--ease-in-out`).
- The brain's highlight, its lean toward the cursor, and every page flip use a small spring (`lib/spring.ts`), parameterised by response and damping. Any of them can be interrupted and reversed mid-motion.
- `prefers-reduced-motion`: no pulses, trail, lean or fly-in; the halves crossfade instead. Page flips become crossfades.
- `prefers-reduced-transparency` and `prefers-contrast` are respected. Hover effects only apply on devices that actually hover. The two halves of the home page are real links, so keyboard and screen-reader users can reach both sides.
